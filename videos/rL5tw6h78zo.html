Actionable Insights

  • Start with one observable behavior, such as dragging a recorder’s camera bubble, rather than asking for a Loom replacement. In a proposed feature-spec.md, record the input, expected output, failure cases, and features you explicitly exclude. Nate’s recorder example at 3:33 separates recording functionality from Loom’s appearance and cloud storage. Evaluate your version against those recorded behaviors, not against a screenshot alone.
  • Read the REA repository and choose an inspection path before setup. Its documentation distinguishes JavaScript/Electron inspection from native analysis using Hopper, Ghidra, or IDA. The documented setup command is npx rea-agents setup, from the repository rather than the video. Review the package and proposed configuration changes first, use a disposable project, and check the current runtime prerequisites. Installing investigation instructions alone does not install the complete tool connection.
  • Keep a proposed evidence.md with separate observed, inferred, and unknown findings. Attach file locations or test results to observed claims. At 9:39 the creator explains why treating inference as fact can corrupt the rebuild. Turn each inference that affects behavior into a test, and leave inaccessible server behavior unknown rather than asking the model to invent an implementation history.
  • Save the investigation summary and retrieve detailed artifacts only when a specific question requires them. At 8:38–9:39, the creator describes a Loom analysis exceeding a gigabyte and warns against repeating it. That size is his report, not a measurement from this run. Record the target version and artifact locations so a later agent can reuse evidence without assuming an old analysis describes a changed app.
  • Build a comparison suite before declaring parity. For the recorder example, proposed checks include pause/resume, bubble movement and resizing, window selection, and playback of the saved local file. Record expected and actual results. Claude Code’s verification guidance supports tests and screenshot comparisons, but passing these checks would establish only the tested behavior, not equivalence to all of Loom.
  • Check authorization and data exposure before inspecting a commercial app. Prefer your own software or an explicitly permitted target for a first experiment. REA’s local analysis does not imply that an agent’s model provider receives no tool output. Avoid private customer data, copied assets, and access-control bypasses. For redistribution or disputed license terms, obtain advice for the relevant jurisdiction rather than treating local possession as permission.

Core thesis

A reference product gives a coding agent a more specific target than a generic request. REA adds a structured investigation process and real inspection tools. The useful outcome is an evidence-backed reconstruction of selected behavior, not a promise that an agent can recover every product’s implementation.

The video is strongest when it narrows scope and distinguishes seen, inferred, and unknown evidence. Its broad framing of reference-based design as decompilation blurs two different activities. Studying a finished animation is not the same technical process as translating compiled machine instructions into pseudocode.

Deep research

Sources were retrieved on 2026-10-14. Web search was unavailable, but direct web retrieval worked.

REA is more than a prompt collection

The official repository describes an MCP connection plus matching workflow instructions. It documents native pseudocode and assembly, JavaScript module relationships, website observations, and other target-specific outputs. Native analysis can use Hopper, Ghidra, or IDA; static JavaScript inspection does not require a native engine. This supports the video’s technology-routing advice and corrects any impression that downloading a skill alone supplies all capabilities.

The same source distinguishes static inspection from runtime capture, which interacts with targets using the user’s permissions. It also states that analysis is local while the agent receives results. These are meaningful operating limits. They contradict an interpretation of REA as either an unrestricted remote-code recovery service or a tool that necessarily keeps every finding away from model providers.

The README cites a DX-Ball reconstruction passing 3,205 original-x86 cases and reproducing all 63 compiled function bytes. This is a project-reported, narrow example, not an independently reproduced benchmark here. It supports the possibility of precise reconstruction under suitable conditions, not the commenter’s claim that any feature eventually becomes exact.

Examples and tests help, but do not settle creativity or speed

Anthropic’s best-practices guide recommends specific context, reference patterns, screenshots, and checks an agent can execute. It also recommends exploration before implementation when a task is uncertain, while warning that planning adds unnecessary overhead for small, clear changes. This supports Nate’s practical method without establishing that every task benefits from a full REA investigation.

Neither that guide nor the video supplies a controlled test of the claim that AI cannot be creative. The creator’s own admission that the reference motion edit remains better is a more defensible, example-specific conclusion. Likewise, his faster-versus-better comparison lacks task counts, scoring criteria, model controls, and cost records.

Local possession does not resolve legality

17 U.S.C. § 1201 prohibits certain circumvention of access controls and includes a conditional interoperability exception in subsection f. That exception has requirements, including lawful access and a specific interoperability purpose. It is not general permission to clone products. This U.S. source complicates the video’s reassurance. It also shows why the comment’s claim that reverse engineering paid software is usually illegal requires more analysis than citing a EULA alone. It does not determine the applicable law or enforceability of a particular EULA.

Recommended workflow and my read

Use an authorized reference, isolate one behavior, record evidence, then implement and compare. Stop investigating when the available evidence answers the scoped question, rather than collecting an entire application by default. Keep unknown internals separate from choices you make in your own design.

The best lesson is to replace vague instructions with observable requirements. A small recorder that reliably meets your needs can be useful without reproducing Loom’s backend, security model, or maintenance organization.
